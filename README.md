# Jana Address

Парсер разбирает сырые адресные строки Казахстана на поля: область, город,
район, микрорайон, улица, дом, квартира, подъезд, этаж, ориентир. Понимает
русский, казахский и латиницу, слитные записи и опечатки.

Всё работает офлайн. Внешних API нет, при разборе сеть не используется.
Внутри обычные правила и справочники (КАТО и OSM), никакого ML.

## Запуск

Нужен Node.js 18+. Зависимостей у бэкенда нет, `npm install` не нужен.

```bash
node src/repl.js "ул. Абая 33/1 кв 12а"      # разобрать одну строку
npm run repl                                  # интерактивный режим
npm run parse -- data/official/sample_input.json -o out.json
npm run serve                                 # API + веб-интерфейс на :8080
```

Пример:

```
$ node src/repl.js "город Актобе/Ақтөбе қаласы, улица Абая 12"
{
  "province": "Актюбинская область",
  "city": "Актобе",
  "district": null,
  "living_area": null,
  "street_type": "улица",
  "street_name": "Абая",
  "house": "12",
  "apartment": null,
  "entrance": null,
  "floor": null,
  "landmark": null,
  "confidence": 0.89
}
```

CLI принимает JSON-массив, один объект или JSONL. Адресную строку ищет в полях
`raw_address`, `address`, `raw`, `address_str`. Поля `id` и `raw_address`
проходят в результат без изменений, записи не теряются.

## Как устроено

`parseAddress(raw)` идёт в четыре шага:

1. нормализация строки;
2. вытаскивание того, что написано явно: дом, квартира, подъезд, этаж,
   область, район, город;
3. разбор остатка: тип и название улицы или микрорайона, ориентир;
4. дозаполнение пустых `province`, `city`, `district` по справочникам.

Поля из строки никогда не перезаписываются. Шаги 1–3 делает `src/parser.js`,
который ничего не знает о справочниках. Шаг 4 живёт отдельно
в `src/resolver.js`, а общая точка входа с обогащением это `src/enrich.js`.

Пара деталей, которые стоит знать:

- `\b` в JS не работает с кириллицей, поэтому границы слов заданы явными
  lookaround-классами в `src/lexicon.js`.
- Найденные фрагменты вычёркиваются по битовой маске позиций, а не срезами:
  после первого удаления индексы иначе уезжают.

Неоднозначные названия остаются `null`. «Туран» есть в Астане, Шымкенте
и Караганде, «Абая» почти везде, поэтому город наугад не подставляется.

## Поля результата

| Поле | Тип | Что означает |
| :--- | :--- | :--- |
| `id` | string \| null | из входной записи, как есть |
| `raw_address` | string | исходная строка, как есть |
| `province` | string \| null | область или город республиканского значения |
| `city` | string \| null | город без слов «город», «пос.» |
| `district` | string \| null | район без слова «район» |
| `living_area` | string \| null | микрорайон/ЖК, если улица указана отдельно |
| `street_type` | string \| null | улица / проспект / переулок / микрорайон / квартал |
| `street_name` | string \| null | название без типа, как в строке |
| `house` | string \| null | с дробью и литерой («1/2», «12а») |
| `apartment` | string \| null | только номер |
| `entrance` | string \| null | только номер |
| `floor` | string \| null | только номер |
| `landmark` | string \| null | ориентир из строки |
| `confidence` | number | эвристика 0..1, в метрику не входит |

Незаполненное поле равно `null`. Код КАТО есть в справочнике, но в результат
не попадает. Достать его можно через `lookupPlace(name)` или
`GET /api/lookup`.

## API

`npm run serve` поднимает сервер на `node:http` без фреймворков
(порт из `PORT`, по умолчанию 8080).

| Метод | Путь | Что делает |
| :--- | :--- | :--- |
| GET | `/api/health` | статус и версия справочника КАТО |
| POST | `/api/parse` | одна запись `{ raw_address }` |
| POST | `/api/parse/batch` | пакет записей, массив на вход и на выход |
| GET | `/api/lookup?name=` | что известно справочнику о названии |
| GET | `/` и `/data/*` | веб-интерфейс и примеры файлов |

```bash
curl -s localhost:8080/api/parse -H 'content-type: application/json' \
  -d '{"raw_address":"Ул. Курильская 9 кв 1"}'
```

Лимит тела запроса 32 МБ. Кривой ввод возвращает 400/413/404, сервер
не падает.

Фронтенд на Vue 3 + Vite, исходники в `web/`. Собранный `web/dist` лежит
в репозитории, поэтому `npm run serve` отдаёт интерфейс сразу. Он умеет
загружать JSON/JSONL файл, разбирать пакет, править результат руками
(записи с низким confidence подсвечены, есть фильтр) и выгружать JSON
кнопкой `download json`.

После правок фронтенда пересоберите его:

```bash
npm run build:web
```

Для живой разработки: `npm run serve` на :8080 и `npm run dev:web`
на :5173 с проксированием `/api`.

## Docker

```bash
docker compose up --build     # → http://localhost:8080
```

Образ multi-stage на `node:22-alpine`. Справочники и `web/dist` запечены
внутрь, поэтому при запуске и разборе сеть не нужна.

## Метрика

Формула из ТЗ, проверка на официальном наборе из 30 записей
(`data/official/`), результат 100%:

```
score = 0.60 * accuracy(province, city, street_name, house)
      + 0.25 * accuracy(apartment, entrance, floor)
      + 0.15 * accuracy(district, living_area)
```

`district` и `living_area` считаются только по записям, где они есть
в исходной строке. Запустить: `npm run eval`, для своих предсказаний
`npm run eval -- --pred my.json`.

## Ограничения

- Одна строка это один адрес. Если склеены несколько, берётся одна,
  приоритет у улицы с явным типом.
- Уличный справочник покрывает 20 городов. Дальше восстановление города
  по улице не работает.
- Падежи не нормализуются, `street_name` остаётся как в строке.

## Пересборка справочников

Все данные уже в `data/`, сеть нужна только при обновлении:

```bash
npm run build:kato        # XLSX Бюро нацстатистики → data/kato/reference.json
npm run fetch:osm         # Overpass → data/osm/<город>.json
npm run build:gazetteer   # OSM + data/manual → data/gazetteer.json
```

Ручные уточнения (например, микрорайон, которого нет в OSM) кладутся
в `data/manual/*.json`, они имеют приоритет.
