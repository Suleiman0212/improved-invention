# Jana Address — разбор адресных строк Казахстана

Парсер берёт произвольную адресную строку — на русском, казахском или латиницей,
слитно, с опечатками и мусором — и раскладывает её в поля: область, город, район,
микрорайон, тип и название улицы, дом, квартира, подъезд, этаж, ориентир.
Работает локально, без внешних API: в момент разбора сеть не используется.

Разбор — это набор правил и справочников, а не модель машинного обучения.
Строки у клиентов очень неоднородны, поэтому понятная и воспроизводимая логика
здесь практичнее: любое правило можно найти в коде и поправить руками.

---

## Запуск

Нужен только **Node.js ≥ 18** (проверено на 22). Внешних зависимостей у бэкенда нет —
`npm install` не требуется.

```bash
node src/repl.js "ул. Абая 33/1 кв 12а"   # разобрать одну строку
npm run repl                               # интерактивный режим, .help / .exit
npm run parse -- data/official/sample_input.json -o out.json   # пакетный разбор
npm run serve                              # REST API + веб-интерфейс на :8080
npm run eval                               # метрика на официальном наборе
```

Пример:

```
$ node src/repl.js "город Актобе/Ақтөбе қаласы, улица Абая 12"
{
  "province": "Актюбинская область",
  "city": "Актобе",
  "district": null,
  "living_area": null,
  "street_type": "улица",
  "street_name": "Абая",
  "house": "12",
  "apartment": null,
  "entrance": null,
  "floor": null,
  "landmark": null,
  "confidence": 0.89
}
```

CLI принимает JSON-массив, один объект или JSONL; исходную строку ищет в полях
`raw_address | address | raw | address_str`. Поля `id` и `raw_address` переносятся
в результат без изменений, записи никогда не пропускаются.

Подробное описание каждого файла и устройства парсера — в [ОПИСАНИЕ.md](ОПИСАНИЕ.md).

## Как это работает

```
parseAddress(raw)
  1. нормализация строки
  2. извлечение того, что явно написано: дом, квартира, подъезд, этаж, область, район, город
  3. разбор остатка: тип и название улицы / микрорайона, дом, ориентир
  4. дозаполнение пустых полей по справочникам (КАТО и OSM) — только если их не было в строке
```

Порядок важен. Сначала вынимаются однозначные поля (числовые и административные),
потом остаток чистится от служебных слов, и только затем в нём ищутся улица
и ориентир — иначе слова-маркеры и номера домов мешают друг другу.

Модуль парсера (`src/parser.js`) ничего не знает о справочниках — он извлекает только
то, что есть в тексте. Дозаполнение живёт отдельно (`src/resolver.js`), поэтому парсер
самостоятелен. Точка входа с обогащением — `src/enrich.js` → `parseAddress`.

Ключевые технические моменты:

- `\b` в JavaScript не работает по кириллице, поэтому границы слов заданы явными
  lookaround-классами `(?<![LETTER])` / `(?![LETTER])` (`src/lexicon.js`).
- Найденные сущности вычёркиваются по битовой маске исходной строки, а не срезами —
  иначе индексы после первого удаления уезжают.
- `street_name` сохраняется ровно как в строке: падежи и опечатки не исправляются.
- Длинные и «мусорные» строки обрезаются до 2048 символов перед разбором.

### Дозаполнение полей и справочники

Если после парсера `province`, `city` или `district` пусты, `src/resolver.js` пытается
добрать их — но только пустые поля и только по надёжным источникам. Значения из
строки никогда не перетираются.

**КАТО** (`data/kato/reference.json`) — классификатор административных объектов РК,
собранный из файла Бюро национальной статистики. По городу даёт область и район
(если район уникален), по району — область. Отдельно обрабатывается указание района
вместо города: «Турксибский район» → город Алматы.

**Уличный справочник OSM** (`data/gazetteer.json`) — название улицы, микрорайона
или посёлка → город и область. Нужен там, где КАТО не спасает: «жуалы 19» →
Алматы, «Пришахтинск…» → Караганда. Покрывает 20 крупных городов. Поиск идёт по
точному ключу, затем по усечённому стему («Назарбаева» → «назарбаев»).

Неоднозначные названия намеренно остаются `null`: «Туран» есть в Астане, Шымкенте
и Караганде, «Абая» — почти везде. Если справочник не даёт однозначного ответа,
город наугад не подставляется. Восстановление срабатывает, когда номинация практически
однозначна — весь индекс указывает на один город, либо кандидатов не больше двух
и лидер набирает не менее 60% упоминаний. Если в строке явно написана область,
данные OSM из другого региона игнорируются.

Поле `living_area` заполняется, только когда улица указана отдельно. Для строки
«Мкр Аксай За, 59, кв 70» микрорайон идёт в `street_name` с типом `микрорайон`,
а `living_area` остаётся `null`. Район внутри города восстанавливается по улице
или микрорайону, когда город уже известен: «Мкр Аксай За» → Ауэзовский район Алматы.

## Поля результата

| Поле | Тип | Что означает |
| :--- | :--- | :--- |
| `id` | string \| null | из входной записи, без изменений |
| `raw_address` | string | исходная строка, без изменений |
| `province` | string \| null | область или город республиканского значения |
| `city` | string \| null | город без слов «город», «пос.» |
| `district` | string \| null | район без слова «район» |
| `living_area` | string \| null | микрорайон/ЖК, если улица указана отдельно |
| `street_type` | string \| null | улица / проспект / переулок / микрорайон / квартал |
| `street_name` | string \| null | название без типа, как в строке |
| `house` | string \| null | с дробью и литерой («1/2», «12а») |
| `apartment` | string \| null | только номер |
| `entrance` | string \| null | только номер |
| `floor` | string \| null | только номер |
| `landmark` | string \| null | ориентир из строки |
| `confidence` | number | 0..1, эвристика (в метрику не входит) |

Неопределённое поле — `null`. Код КАТО держится внутри как полезная нагрузка
справочника, но в результат разбора не включается — в спецификации такого поля нет.
Достать его можно через `lookupPlace(name)` или `GET /api/lookup`.

### Метрика

Формула из ТЗ (`scripts/evaluate.js`), посимвольное совпадение после нормализации:

```
score = 0.60 * accuracy(province, city, street_name, house)
      + 0.25 * accuracy(apartment, entrance, floor)
      + 0.15 * accuracy(district, living_area)
```

`district` и `living_area` входят в метрику только по записям, где они физически
присутствуют в исходной строке. `street_type`, `landmark` и `confidence` в балл
не входят. На официальном наборе из 30 записей (`data/official/`) результат — 100%.

```bash
npm run eval                     # текущее решение на data/official/
npm run eval -- --pred my.json   # свои предсказания
```

## API и веб-интерфейс

`npm run serve` поднимает `server/app.js` на стандартном `node:http` без фреймворков
(порт из `PORT`, по умолчанию 8080). Сервер отдаёт и веб-интерфейс, и API.

| Метод | Путь | Назначение |
| :--- | :--- | :--- |
| GET | `/api/health` | статус и версия справочника КАТО |
| POST | `/api/parse` | одна запись `{ raw_address } → результат` |
| POST | `/api/parse/batch` | пакет записей → массив результатов |
| GET | `/api/lookup?name=` | что известно справочнику о названии |
| GET | `/` и `/data/*` | веб-интерфейс и примеры файлов |

```bash
curl -s localhost:8080/api/parse -H 'content-type: application/json' \
  -d '{"raw_address":"Ул. Курильская 9 кв 1"}'
```

Лимит тела запроса — 32 МБ; некорректный ввод возвращает 400/413/404 без падения
сервера.

Фронтенд живёт в `web/` (Vue 3 + Vite). Собранный интерфейс лежит в `web/dist`,
поэтому `npm run serve` открывает UI сразу — без установки зависимостей и сборки.
Пересобирать нужно только после правок фронтенда (нужен Node 22.18+ для Vite 8):

```bash
npm run build:web            # npm --prefix web install && npm --prefix web run build
```

Для живой разработки вместо сборки поднимается Vite с проксированием `/api`:

```bash
npm run serve                # бэкенд на :8080
npm run dev:web              # Vite на :5173, /api проксируется на :8080
```

Интерфейс позволяет загрузить файл (JSON/JSONL — чтение в браузере), разобрать
пакет, посмотреть результат таблицей, вручную поправить неуверенные поля
(записи с низким confidence подсвечиваются, есть фильтр «только низкий
confidence») и выгрузить итоговый JSON кнопкой «download json» — уже с учётом
правок.

## Docker

```bash
docker compose up --build     # → http://localhost:8080
```

`Dockerfile` — multi-stage: сборка справочника КАТО, сборка веб-интерфейса и
рабочий образ на `node:22-alpine`. `data/kato/reference.json`, `data/gazetteer.json`
и собранный `web/dist` запекаются внутрь, поэтому в момент прогона сеть не нужна.

## Пересборка справочников

Скрипты ниже обращаются к сети и нужны только при обновлении данных; в обычной
работе сеть не используется — все данные уже лежат в `data/`.

```bash
npm run build:kato        # XLSX Бюро нацстатистики → data/kato/reference.json
npm run fetch:osm         # Overpass → data/osm/<город>.json
npm run build:gazetteer   # OSM + data/manual → data/gazetteer.json
```

Ручные уточнения (например, микрорайон, которого нет в OSM) кладутся
в `data/manual/*.json` — они имеют приоритет над OSM.

## Ограничения

- **Одна строка — один адрес.** Если в строке склеены несколько улиц и домов,
  берётся одна (приоритет у улицы с явным типом).
- **Уличный справочник покрывает 20 городов.** За их пределами восстановление
  города по улице не работает.
- **Неоднозначные названия остаются `null`** — это осознанный выбор, а не пропуск.
- **Падежи улиц не нормализуются** — название сохраняется как в строке.
